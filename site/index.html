지금 로컬에서 실행 ↓ 계정 화면 열기 ↗

  1. Google로 로그인

    Google이 인증을 처리합니다. skillar는 Google ID, 이메일, 이름, 사진과 최초·최근 로그인 시각을 저장합니다. 세션은 서명된 보안 쿠키로 유지하며 Google 토큰은 보관하지 않습니다.

  2. 기기 연결

    대시보드에서 일회성 승인 파일을 내려받아 로컬 CLI를 연결하세요. 이후 해당 기기의 업로드 동의를 별도로 저장하세요. 연결만으로 업로드하지 않습니다.

  3. 활동 확인

    업로드한 기록을 세션, 작업 공간, 사용 흐름과 활동 분포에서 확인하세요. 동의한 업로드가 바뀌면 화면이 갱신되며, 수집 시각과 보고서 상태로 최신 여부를 확인할 수 있습니다.

로컬 CLI는 런타임 감지, MCP 설정과 백그라운드 서비스 설치를 지원합니다. 적용하기 전에 변경 내용을 미리 확인하세요.

새로 설치 · macOS 또는 Linux · Node.js 24.15+

gisool에서 업그레이드한다면 먼저 이전하세요 ↗
npm install -g skillar

이후 skillar init을 실행하세요. gisool 위에 설치하면 gisool 명령이 충돌하므로 먼저 이전하세요.

터미널로컬 설정
# 파일을 바꾸지 않고 미리 확인
skillar init --dry-run

# 런타임 연결과 백그라운드 서비스 설치
skillar init

# 스킬 활동 확인
skillar open

포그라운드 실행을 원하면 위 서비스 설치 대신 skillar init --no-service 실행 후 skillar serve를 실행하세요.

자주 묻는 질문

에이전트 스킬이란 무엇인가요?

SKILL.md 지침과 선택적인 보조 파일을 담은 폴더입니다. 이름과 설명은 에이전트의 검색을 돕고, 본문은 실제 지침을 담습니다.

지금 skillar를 사용할 수 있나요?

네. npm install -g skillar로 로컬 CLI를 설치하고 skillar init --dry-run으로 변경 내용을 미리 확인하세요. macOS 또는 Linux와 Node.js 24.15 이상이 필요합니다. gisool에서 업그레이드한다면 먼저 이전 안내를 읽으세요.

호스팅 서비스를 이용할 수 있나요?

네. skillar.sh/skills에서 비공개 스킬과 버전을 관리하고, OAuth로 Codex 또는 Claude Code를 https://skillar.sh/mcp에 연결해 게시한 스킬을 읽을 수 있습니다. 활동 업로드에는 기기 연결과 별도의 명시적 동의가 필요합니다. 호스팅 요금은 아직 발표되지 않았습니다. 호스팅 계정 안내에서 이용 순서를 확인하세요.

모든 MCP 클라이언트에서 작동하나요?

MCP 리소스를 검색하고 읽을 수 있는 호스트가 필요합니다. 저장소에 런타임별 연동이 있지만 호환성과 기록 범위는 다릅니다. 클라이언트의 프로토콜·호환성 안내를 확인하세요.

로컬 데이터는 어디에 저장되나요?

로컬 데몬은 루프백에서 수신하고 로컬 인증 토큰을 사용하며 색인한 스킬과 세션 활동을 로컬 SQLite에 저장합니다. 클라우드 업로드는 기본으로 꺼져 있습니다. 기기를 연결하고 대시보드에서 업로드에 명시적으로 동의해야 켜집니다. 연결한 에이전트와 모델 제공자는 데이터를 별도로 처리합니다.

팀 저장소를 직접 운영할 수 있나요?

네. 저장소에는 비공개 R2 배포본을 인증해 제공하는 Node.js 저장소와 Cloudflare Worker가 포함됩니다. 인프라와 인증 정보는 직접 준비해야 합니다. 배포 안내.

이름의 출발점은 기술 — 지식과 솜씨입니다.
